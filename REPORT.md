# Звіт до лабораторної роботи № 1

## 1. Тема, номер і варіант

Лабораторна робота № 1.

Предметна область: спортивні тренування.

Варіант: 2.

Операційна система: macOS.

## 2. Мета роботи

Розробити консольну Java-програму для читання та перевірки даних про спортивні тренування, обчислення заданих показників і формування звіту.

Також налаштувати збірку Maven, автоматичні тести, статичний аналіз коду та перевірку проєкту через GitHub Actions на різних операційних системах.

## 3. Постановка задачі

Один запис про тренування має такий формат:

`date;kind;minutes;distanceKm;calories`

Поля:
- `date` — дата тренування;
- `kind` — вид тренування;
- `minutes` — тривалість у хвилинах;
- `distanceKm` — дистанція в кілометрах;
- `calories` — витрачені калорії.

Програма повинна обчислити:
1. кількість коректних тренувань;
2. сумарний час тренувань;
3. сумарну дистанцію;
4. найбільшу витрату калорій.

Некоректний запис не повинен завершувати роботу всієї програми. Для такого запису потрібно показати номер рядка та причину помилки.

## 4. Структура програми

Вхідні дані зберігаються у файлі `data/input.csv`.

Загальний потік обробки:

`читання файла → перевірка записів → обчислення показників → формування звіту → виведення у консоль і файл`

Для предметної частини лабораторної створено Issues:

## 7. Приклади роботи

Вхідний файл містить коректні та хибні записи.

Приклад:

```text
2026-09-10;Біг;45;8.5;620
2026-09-12;Велосипед;60;21.4;540
2026-09-15;Плавання;50;2.1;430
2026-09-17;Ходьба;-30;3.0;180
2026-09-20;Йога;abc;0.0;200
```
Фактичний результат запуску:

```text
Рядок 4 пропущено: числові значення не можуть бути від'ємними.
Рядок 5 пропущено: неправильне числове значення.

Звіт про спортивні тренування
Коректних записів: 3
Сумарний час: 155 хв
Сумарна дистанція: 32.00 км
Максимальна витрата калорій: 620

Звіт збережено у: data/report.txt
```

## 8. Тестування

Для тестування предметної логіки використано JUnit 5.

Перевірено:
- правильне обчислення показників для кількох коректних записів;
- порожній рядок;
- неправильну кількість полів;
- текст замість числового значення;
- від'ємне числове значення;
- порожнє обов'язкове поле;
- роботу з українським текстом.

Команда запуску тестів:

```bash
./mvnw test
```

Результат:

```text
Tests run: 7, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

Також виконано повну перевірку проєкту:

```bash
./mvnw clean verify
```

Результат:

```text
Tests run: 7, Failures: 0, Errors: 0, Skipped: 0
BugInstance size is 0
Error size is 0
No errors/warnings found
BUILD SUCCESS
```

Таким чином, усі JUnit-тести пройдено успішно, а SpotBugs не виявив помилок або попереджень.

Посилання на фінальний запуск GitHub Actions та артефакти буде додано після створення Pull Request.

Для організації процесу були підготовлені окремі ролі:
- Менеджер;
- DevOps;
- Розробник;
- Валідатор;

- Рецензент.

ШІ використовувався для уточнення вимог методичних вказівок, планування GitHub Issues, роботи з Git, Maven і GitHub Actions, а також для рекомендацій щодо покращення структури програми, тестування та документації.

Під час реалізації програми ChatGPT використовувався для перевірки окремих рішень і рекомендацій щодо їх покращення, зокрема для уникнення можливих помилок під час роботи з файлами, числовими значеннями, аргументами командного рядка та перевіркою вхідних даних. Для запропонованих змін також пояснювалося їх призначення і те, яку проблему вони допомагають вирішити.

Коректність роботи перевірялася локальним запуском програми, JUnit-тестами, Maven `verify` та SpotBugs.

Під час фінальної перевірки реальних дефектів не виявлено, тому окремий GitHub Issue з міткою `bug` не створювався.

## 11. Відповіді на контрольні питання

### 1. Яке призначення файла pom.xml?

`pom.xml` описує Maven-проєкт: його назву, версію, Java-версію, залежності, плагіни та правила збірки.

### 2. Чим відрізняються фази test, verify і package у Maven?

`test` компілює проєкт і запускає тести. `package` додатково створює JAR. `verify` виконує перевірки проєкту, зокрема в нашому випадку SpotBugs.

### 3. Навіщо потрібен Maven Wrapper?

Maven Wrapper дозволяє запускати потрібну версію Maven через `mvnw` або `mvnw.cmd`, навіть якщо Maven окремо не встановлений у системі.

### 4. Яку роль відіграє метод main?

`main` є точкою входу в Java-програму. З нього починається виконання програми та обробка аргументів командного рядка.

### 5. Чим примітивний тип відрізняється від String?

Примітивні типи зберігають прості значення, наприклад `int` або `double`. `String` є класом і використовується для роботи з текстом.

### 6. Чому середнє потрібно обчислювати в double, навіть якщо сума й кількість мають тип int?

Тому що результат ділення може бути дробовим. Якщо використовувати тільки `int`, дробова частина буде втрачена.

### 7. Що станеться, якщо Integer.parseInt отримати рядок "abc"?

Буде створено виняток `NumberFormatException`. У програмі такі помилки потрібно обробляти, щоб один неправильний рядок не завершив усю програму.

### 8. Чому не можна мовчки пропускати рядок із помилкою?

Користувач повинен знати, що саме було неправильним. Тому програма показує номер рядка та причину його пропуску.

### 9. Як String.split(";", -1) обробляє порожнє останнє поле?

Параметр `-1` дозволяє зберегти порожнє поле в кінці рядка. Це дає змогу правильно визначити, що значення відсутнє.

### 10. Чому для шляхів краще використовувати Path.of, а не "data\\input.csv"?

`Path.of` працює платформонезалежно і не прив'язує шлях до конкретного формату Windows.

### 11. Навіщо явно задавати StandardCharsets.UTF_8?

Щоб файл однаково читався на різних операційних системах і правильно обробляв українські символи.

### 12. Чим %n відрізняється від \n у форматованому виводі?

`%n` використовує правильний для поточної операційної системи символ переносу рядка, а `\n` задає конкретний символ.

### 13. Які дані потрібно перевірити у вашому варіанті?

Потрібно перевірити кількість полів, наявність дати та виду тренування, правильність числових значень `minutes`, `distanceKm` і `calories`, а також відсутність від'ємних чисел.

### 14. Які тести виявлять помилку в обчисленні середнього?

Потрібні тести з кількома відомими значеннями, для яких середнє можна заздалегідь порахувати вручну, особливо коли результат має дробову частину.

### 15. Яке призначення статичного аналізатора?

Статичний аналізатор перевіряє код без його запуску та допомагає знаходити потенційні помилки й проблемні конструкції. У роботі використано SpotBugs.

### 16. Яку роль виконує GitHub Actions?

GitHub Actions автоматично запускає збірку та перевірки після змін у репозиторії. У цьому проєкті він перевіряє програму на Ubuntu, Windows і macOS.

### 17. Що має містити GitHub Issue на дефект?

Issue на дефект має містити опис проблеми, кроки відтворення, очікуваний результат і фактичний результат.

### 18. Що потрібно вказати у розділі звіту про академічну доброчесність?

Потрібно вказати використані інструменти ШІ, ролі, для яких задач вони застосовувалися, прийняті рекомендації, знайдені або виправлені помилки та підтвердити розуміння поданого коду.

### 19. Яку роботу виконує агент DevOps, а яку агент Валідатор?

DevOps працює з Maven, Wrapper, CI, аналізатором і пакуванням. Валідатор перевіряє програму на коректних і крайових випадках, аналізує результати тестів та допомагає оформлювати знайдені дефекти.

## 12. Висновки

У лабораторній роботі створено консольну Java-програму для обробки даних про спортивні тренування.

Програма читає CSV-файл, перевіряє записи, пропускає хибні дані з поясненням причини, обчислює задані показники та формує звіт у консолі й текстовому файлі.

Для проєкту налаштовано Maven, Maven Wrapper, JUnit 5, SpotBugs, виконуваний JAR і GitHub Actions. Предметну логіку перевірено сімома автоматичними тестами, а команда `./mvnw clean verify` завершується успішно.

Структура програми залишає окремими обробку даних і формування звіту, що можна використати як основу для наступної лабораторної роботи, де рядкові записи будуть замінюватися власними класами.

Фінальні дані про Pull Request, GitHub Actions, версію `1.0.0`, Git-тег `v1.0.0` та JAR-артефакти будуть додані після фінального злиття гілки.
