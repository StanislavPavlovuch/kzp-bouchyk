## 4. Спільний тип і обґрунтування архітектури

Основний базовий клас `Training` оголошено як `sealed` із дозволеними підтипами `IndoorTraining` і `OutdoorTraining`. Він містить спільні `private final` поля `date`, `kind`, `minutes`, `distanceKm`, `calories`, інваріанти та методи читання. Вибрано **спадкування** (`IndoorTraining extends Training`, `OutdoorTraining extends Training`), тому що підтипи є різновидами тренувань, а не об'єктами, які лише містять тренування.

Спільний **інтерфейс `LoadCalculable`** задає абстрактний контракт `calculateLoad()`. `Training` лишається конкретним навмисно: старі тести створюють `new Training(...)`, тому зміна на `abstract class Training` зламала б сумісність із ЛР №2. Через інтерфейс виконано вимогу спільного абстрактного контракту, через `Training` — вимогу спільних полів та повторного використання коду.

## 5. Підтипи й поліморфний метод

- `IndoorTraining`: навантаження = `minutes * 1.2 + calories * 0.10`.
- `OutdoorTraining`: навантаження = `minutes + distanceKm * 10.0 + calories * 0.10`.
- Звичайний `Training` для інших видів: `minutes + calories * 0.10`.

Ці коефіцієнти визначені як навчальні **умовні одиниці**, не медична оцінка інтенсивності. Різниця поведінки підтверджується тестом з однаковими вхідними числами: 46.00 у.о. для Indoor, 80.00 у.о. для Outdoor.

## 6. enum

`TrainingKind` має значення `INDOOR`, `OUTDOOR`, `OTHER` з українськими підписами. Статичний метод `fromActivity(String)` класифікує старе поле CSV `kind`; невідому активність зберігає коректною як `OTHER`. Для демонстраційних даних плавання віднесено до тренування в критому басейні.

## 7. equals і hashCode

Рівність визначається за конкретним класом об'єкта та п'ятьма полями CSV. `getClass()` не допускає рівності різних підтипів; `Double.compare()` відповідає за порівняння дистанції. `hashCode()` побудовано за тим самим набором компонентів.

Тести перевіряють симетричну рівність двох однакових об'єктів, однаковий hashCode, нерівність підтипів і те, що `HashSet` зберігає один елемент для двох логічно однакових об'єктів.

## 8. Поліморфна колекція

`TrainingLoadAnalyzer.summarize(List<? extends Training>)` працює з об'єктами через базовий тип `Training`:

```java
for (Training training : trainings) {
    double load = training.calculateLoad();
    total += load;
    maximum = Math.max(maximum, load);
}
```

Завдяки динамічному зв'язуванню JVM викликає потрібний перевизначений метод. У циклі **немає** `if`, `instanceof` або `switch` за підтипом. Вибір підтипу централізовано виконано лише під час створення об'єкта фабрикою `fromCsv`.

## 12. Порівняння поведінки

Контрольний CSV `data/input.csv` містить 3 правильні та 2 неправильні записи. Попередня реалізація формувала:

```text
Звіт про спортивні тренування
Коректних записів: 3
Сумарний час: 155 хв
Сумарна дистанція: 32.00 км
Максимальна витрата калорій: 620
```

Нова реалізація зберігає формування цього звіту через старий `HelloApplication.buildReport()`. Окрема команда `TrainingLoadDemo` додає нову функціональність, не змінюючи старий файл `data/report.txt`.

Фактичний новий поліморфний підсумок на тих самих даних (запуск 23.11.2026): 623.00 у.о. сумарного навантаження та 328.00 у.о. найбільшого навантаження. Стандартний звіт залишився: 3 записи, 155 хв, 32.00 км, 620 калорій.

**Порівняння:** усі чотири контрольні показники ЛР №2 та ЛР №3 збігаються за локальним запуском (3, 155 хв, 32.00 км, 620). Побайтове порівняння `diff` двох версій звіту окремо не запускалося; не заявляється як виконане.

## 14. Відповіді на контрольні питання

1. Базовий тип об'єднує спільні поля та інваріанти, щоб не копіювати їх у Indoor/Outdoor.
2. `extends` успадковує клас, `implements` реалізує контракт інтерфейсу.
3. Абстрактний клас неможливо створити напряму; він може задавати спільний стан і абстрактні методи.
4. `super(...)` передає спільні дані конструктору базового класу до ініціалізації підтипу.
5. `@Override` дозволяє компілятору перевірити фактичне перевизначення методу.
6. Поліморфізм вибирає реалізацію за реальним класом об'єкта, без центральних перевірок типу.
7. Абстрактний клас застосовують для спільного стану, інтерфейс — для поведінкового контракту. У роботі є `LoadCalculable` та клас `Training`.
8. Спадкування означає «є різновидом»; композиція — «містить/використовує» інший об'єкт.
9. `TrainingKind` задає фіксовані категорії з підписами й правилами класифікації.
10. Значення enum — одиничні константи, тому їх можна порівнювати через `==`.
11. Якщо `a.equals(b)`, то `a.hashCode()` має дорівнювати `b.hashCode()`, і рівність має бути рефлексивною, симетричною, транзитивною та послідовною.
12. Якщо змінити поле, що бере участь у hashCode, об'єкт може опинитися в неправильному хеш-бакеті HashMap.
13. Через перевірку `getClass()` навіть однакові CSV-поля в різних підтипів не роблять об'єкти рівними.
14. `List<Training>` зберігає різні підтипи, а `training.calculateLoad()` динамічно викликає їхні реалізації.
15. Тест однакових чисел для Indoor та Outdoor порівнює 46.00 і 80.00 у.о.
16. Два однакові OutdoorTraining, додані в HashSet, дають розмір множини 1.
17. `sealed` обмежує прямі підтипи за допомогою `permits`. У ЛР №3 `Training` запечатано для `IndoorTraining` і `OutdoorTraining`; додатковий `switch` зі зіставленням зі зразком не реалізовано, оскільки це необов'язкове завдання із зірочкою.
18. `switch` за підтипами дублює логіку і вимагає редагування при додаванні нового класу; перевизначені методи цього уникають.
19. Потрібно зберегти всі 21 попередні тести, формули сумарних показників і формат стандартного звіту.
20. Найкраще поліморфізм видно у `TrainingLoadAnalyzer.summarize()`: цикл працює лише з типом `Training`.
